## 2. التشخيص الهيكلي: هل النظام صفحة واحدة (SPA) أم متعدد الصفحات (MPA)؟

### النتيجة الهندسية:
النظام هو **نظام متعدد الصفحات أصيل ومُحسّن (Enhanced Multi-Page Architecture - MPA)**.

### لماذا تم اختيار نظام MPA بدلاً من SPA لبوابات ميكروتك؟
1. **طبيعة خادم ميكروتك المدمج (RouterOS HTTP Web Server):**
   - راوترات ميكروتك لا تحتوي على بيئة تشغيل متقدمة مثل Node.js أو خوادم تدعم توجيهات الـ SPA (مثل fallback URL Rewrite).
   - يعتمد المايكروتك في نواته على استدعاء ملفات ثابتة مرتبطة بحالة الجلسة عبر مصفوفة صفحات كابتيف:
     `login.html` ➔ `alogin.html` ➔ `status.html` ➔ `logout.html`.
2. **التوافق التام مع متصفحات الأجهزة القديمة والحديثة:**
   - متصفحات الـ Captive Portal المنبثقة (مثل Apple CNA في آيفون، و Android CaptivePortalLogin، و Windows NCSI) تكون في بيئة Webview معزولة ومقيدة الصلاحيات.
   - مكتبات الـ SPA الحديثة (مثل React أو Vue) تستهلك ميجابايتات من الذاكرة وتتطلب إصدارات متقدمة من محركات ECMAScript لا تتوفر في الهواتف القديمة (مثل أجهزة أندرويد 4 و 5 و 6، وهواتف كاي أو إس KaiOS ونوكيا)، مما يؤدي لتجمد شاشة الدخول أو ظهور شاشة بيضاء.
3. **سرعة الاستجابة الخاطفة:**
   - الحجم الإجمالي لكل صفحة يتراوح بين **10 إلى 25 كيلوبايت فقط**، مما يتيح تحميل الصفحة في أقل من **50 ميلي ثانية** حتى في أضعف إشارات الواي فاي.
4. **الميزات التفاعلية المدمجة بنظام المكونات المستقلة:**
   - على الرغم من أنه MPA، إلا أنه مزود بمحركات تفاعلية داخلية خفيفة بدون أطر عمل خارجية ثقيلة (Vanilla JS):
     - تغيير السرعة بدون إعادة إدخال الكرت عبر تقنية `Fetch API` و `FormData`.
     - نافذة منبثقة تفاعلية للمحافظ والشراء المباشر.
     - حفظ الكروت واستدعاؤها من الذاكرة المحلية `localStorage`.
     - بنر ثلاثي الأبعاد `3D Carousel` بحسابات زوايا CSS بدون استهلاك للمعالج.

## 5. طرق ومسارات تسجيل الدخول (HTTP PAP, HTTP CHAP, GET Login)

يدعم النظام ثلاث آليات رئيسية للمصادقة متوافقة مع جميع بروفايلات الراوتر:

### 1. طريقة HTTP PAP (الافتراضية المباشرة):
- يتم إرسال اسم المستخدم وكلمة المرور بنص واضح داخل حمولة POST إلى الرابط الافتراضي `$(link-login-only)`:
  ```html
  <form name="login" action="$(link-login-only)" method="post">
      <input type="number" id="uname" name="username" placeholder="رمز الدخول" />
      <input type="hidden" id="passw" name="password" />
      <input type="hidden" name="dst" value="$(link-orig)" />
      <button type="submit">دخول</button>
  </form>
  ```
- ميزة هذه الطريقة: السرعة الفائقة والتوافقية الكاملة 100% مع أجهزة الهواتف الخلوية القديمة والأجهزة اللوحية دون الحاجة لتنفيذ تشفير ثقيل على المعالج.

### 2. طريقة HTTP CHAP (التشفير الآمن بالاستجابة والتحدي):
- إذا كان راوتر ميكروتك مفعلاً فيه خيار `HTTP CHAP`، تظهر كتلة المتغيرات الشرطية:
  ```html
  $(if chap-id)
  <form name="sendin" action="$(link-login-only)" method="post">
      <input type="hidden" name="username" />
      <input type="hidden" name="password" />
      <input type="hidden" name="dst" value="$(link-orig)" />
  </form>
  <script type="text/javascript" src="md5.js"></script>
  $(endif)
  ```
- تقوم دالة `saveVoucher()` بحساب تجزئة MD5 بالمعادلة:
  $$\text{Hash} = \text{hexMD5}(\$(chap-id) + \text{password} + \$(chap-challenge))$$
  ثم إرسال النتيجة المشفرة إلى الراوتر، مما يمنع اعتراض كلمة المرور عبر الهواء.

### 3. طريقة الرابط المباشر (Direct GET Login):
- يدعم النظام الدخول عبر استدعاء الرابط المباشر:
  `http://a.net/login?username=XXXXX&password=XXXXX`
- تُستخدم هذه الطريقة في ميزة إعادة الاتصال السريع وتحديث السرعات من الكوكيز المخزنة.

## 6. نظام السرعات وتحديد القيم وتغيير السرعة من صفحة الحالة

يتميز النظام بهندسة فريدة تتيح التحكم بسرعات الإنترنت في مرحلتين: أثناء الدخول، وأثناء الجلسة النشطة.

### 1. مصفوفة السرعات في صفحة الدخول (`login.html` / `index.html`):
يتم اختيار السرعة عبر القائمة المنسدلة المربوطة بالحقل `name="speed"`:
* **الخيار الأول (`bb1bb2bb3bb4bb5-bb`):** سرعة فائقة / عالية (مخصصة للفيديوهات والتنزيل السريع).
* **الخيار الثاني (`ss1ss2ss3ss5ss7-ss`):** سرعة متوسطة (متوازنة للتصفح واليوتيوب وتطبيقات التواصل).
* **الخيار الثالث (`c1c2c3c4c5c6-pp`):** سرعة اقتصادية (مثالية لتوفير الرصيد والمراسلات وتطبيقات واتساب).

### 2. مصفوفة تعديل السرعة الفورية من صفحة الحالة (`status.html`):
يمكن للعميل تغيير سرعته أثناء استخدامه للشبكة مباشرة دون فقدان رصيده عبر الخيارات:
* `4a4b4c4d4e4f4g-44f`: سرعة اقتصادية.
* `9a9b9c9d9e9f9-99-ba`: سرعة فائقة.
* `8a8b8c8d8e8f8g8h8i-55-sa`: السرعة القصوى.

### 3. آلية تنفيذ تغيير السرعة بالخلفية وإعادة الاتصال:
```javascript
// الكود الفعلي المطبق في status.html
document.getElementById('speed-change-form').addEventListener('submit', function(e) {
    e.preventDefault(); // منع المتصفح من الخروج لروابط خارجية
    
    var logoutUrl = "$(link-logout)"; // رابط إنهاء الجلسة القديمة
    var speedValue = document.getElementById('speed-select').value;
    
    var formData = new FormData();
    formData.append('erase-cookie', 'true');
    formData.append('dst', speedValue); // تمرير السرعة الجديدة في بارامتر dst

    // إرسال الطلب في الخلفية
    fetch(logoutUrl, {
        method: "POST",
        body: formData
    })
    .then(function() {
        // العودة لصفحة الدخول ليتم الدخول التلقائي فوراً بالسرعة الجديدة
        window.location.href = "login.html"; 
    });
});
```
**كيف يعمل هذا على ميكروتك؟**
1. يتم تسجيل خروج العميل من الجلسة القديمة ذات السرعة الحالية.
2. يتم توجيهه إلى `login.html`.
3. تقوم دالة `autoFillAndSubmit()` الذكية بقراءة رقم الكرت من `localStorage` وإعادة إرساله فوراً بالسرعة الجديدة دون أي تدخل يدوي من العميل!

## 7. الماك أدرس (MAC Address) والارتباط بالجهاز وحماية الجلسات المتزامنة

* **جلب عنوان الماك:**
  يتم قراءة ماك العميل تلقائياً بواسطة ميكروتك عبر جدول ARP و DHCP Lease ووضعه في المتغير `$(mac)`.
* **تحديد عدد الجلسات المتزامنة (Shared Users):**
  - مضبوط افتراضياً في بروفايل المستخدم على `Shared Users = 1`.
  - إذا حاول جهاز ثانٍ إدخال نفس الكرت بينما الجلسة قائمة على جهاز أول، يقوم ميكروتك برفض الطلب ويعيد الخطأ:
    `simultaneous session limit reached`
  - يُترجم هذا الخطأ فوراً في البوابة إلى:
    **"الكرت مستخدم في جهاز آخر"**.
* **قفل الكرت على ماك الجهاز الأول (Calling-Station-Id Lock):**
  - عند ربط الكرت بماك الجهاز الأول، يرفض المايكروتك أي جهاز آخر حتى لو كان الكرت مسجلاً خروجه، معيداً:
    `invalid Calling-Station-Id`
  - وتظهر للعميل الرسالة التوضيحية:
    **"لا يمكنك استخدام هذا الرقم، لأنه تم تخصيصه لجهاز آخر"**.

## 8. نظام الكوكيز والتخزين المحلي وإدارة الكروت المحفوظة وحظر الحلقات

تستخدم البوابة نظام حماية وتخزين متعدد المستويات يجمع بين الكوكيز والتخزين المحلي `localStorage`:

### 1. مفاتيح التخزين المحلي (LocalStorage Keys):
1. **`strict_last_uname`:**
   يخزن آخر رقم كرت قام العميل بكتابته بدقة شديدة عند كل حدث إدخال (`input`).
2. **`lastAttemptedVoucher`:**
   يسجل الكرت الذي يتم محاولة تسجيل الدخول به حالياً لتوثيق نتيجته (نجاح أم فشل).
3. **`block_auto_login` (صمام الأمان الذكي):**
   عند حدوث أي خطأ في الكرت (رصيد منتهٍ، كرت مستخدم، خطأ في الرمز)، يتم رفع هذا القفل فوراً إلى `true`. هذا يمنع البوابة من الدخول في **حلقة تكرار لانهائية (Infinite Loop)** لإعادة تسجيل كرت خاطئ مراراً وتكراراً.
4. **`savedVouchers`:**
   مصفوفة JSON تحتوي على سجل الكروت السابقة التي استخدمها العميل مع علامات حالتها التوضيحية:
   - الكرت المنتهي: `{ code: "12345", status: "❌ منتهي" }`
   - الكرت الخاطئ: `{ code: "99999", status: "❌ خطأ" }`
   - الكرت الناجح: `{ code: "77777", status: "" }`

### 2. معالجة وتصحيح الأرقام العربية تلقائياً:
تحتوي البوابة على دالة `convertToArabic2` التي تراقب حقل الإدخال وتقوم بتحويل الأرقام المكتوبة بلوحة المفاتيح العربية (مثل: `١٢٣٤٥٦٧٨٩٠`) إلى أرقام إنجليزية (`1234567890`) مع إزالة الفراغات تلقائياً، مما يمنع أخطاء إدخال الكروت الشائعة على هواتف أندرويد وآيفون.

## 9. محرك ترجمة وإدارة رسائل الخطأ والتنبيهات المترجمة

تتضمن البوابة محركاً برمجياً كاملاً يعترض رسائل ميكروتك الإنجليزية ويحولها إلى العربية في بطاقة تنبيه عصرية:

| رسالة ميكروتك الأصلية | الترجمة التلقائية المعروضة للعميل |
| :--- | :--- |
| `simultaneous session limit reached` | **الكرت مستخدم في جهاز آخر** |
| `invalid password` | **كلمة المرور غير صحيحة** |
| `no valid profile found` | **انتهت صلاحية الرصيد** |
| `user <xxx> not found` | **المستخدم غير موجود** |
| `uptime limit reached` | **انتهى رصيد هذا الكرت** |
| `download limit reached` | **انتهى رصيد هذا الكرت** |
| `transfer limit reached` | **لقد استفرغت كامل رصيد الإنترنت الخاص بهذا الكرت** |
| `invalid Calling-Station-Id` | **لا يمكنك استخدام هذا الرقم، لأنه تم تخصيصه لجهاز آخر** |
| `no more sessions are allowed for user`| **الكرت مستخدم في جهاز آخر** |
| `web browser did not send challenge response` | **أعد المحاولة مرة أخرى، إذا ظهرت هذه الرسالة مجدداً فيجب تفعيل الجافاسكربت** |

## 12. سرعة فتح الصفحة والتوافقية الخارقة مع الأجهزة القديمة والحديثة

تم تصميم واختبار البوابة لتعمل على أوسع شريحة ممكنة من الأجهزة:

1. **الهواتف الذكية الحديثة (Modern Smartphones):**
   - أجهزة iPhone بنظام iOS 12 حتى iOS 18+، وهواتف Android 10 إلى Android 15+.
   - دعم كامل لخاصية ملء الشاشة والشاشات ذات الحواف المنحنية والـ Notches (`viewport-fit=cover`).

   - الحجم الإجمالي لكافة ملفات البوابة المضغوطة أقل من **150 كيلوبايت**، مما يضمن فتح البوابة فور ارتباط الجهاز بنقطة الوصول حتى لو كان البرج يبعد مسافة طويلة وتغطية الإشارة ضعيفة جداً.

## 13. إعدادات راوتر بورد ميكروتك (RouterOS Commands & Profiles)

لرفع وتفعيل هذه البوابة على راوتر ميكروتك، نفّذ الخطوات التالية:

### 1. رفع الملفات إلى مجلد الهوتسبوت:
- عبر برنامج **Winbox**، ادخل إلى قائمة `Files`.
- اسحب كافة ملفات المشروع وضعها داخل مجلد `hotspot` (أو المجلد المخصص للبوابة مثل `hotspot/adeemb`).

### 2. أوامر ضبط السيرفر بروفايل في ميكروتك (Terminal Script):
```routeros
/ip hotspot profile
set [ find default=yes ] \
    html-directory=hotspot \
    login-by=http-pap,http-chap,cookie,mac-cookie \
    http-cookie-lifetime=3d \
    split-user-domain=no \
    use-radius=no

/ip hotspot user profile
set [ find default=yes ] \
    shared-users=1 \
    status-autorefresh=1m \
    transparent-proxy=no
```

### 3. السماح للمحافظ بالعمل قبل تسجيل الدخول (Walled Garden):
لضمان قدرة العملاء على الدخول إلى تطبيقات المحافظ الإلكترونية لشراء كروت دون اشتراك إنترنت مسبق، أضف القواعد التالية:
```routeros
/ip hotspot walled-garden
add dst-host=*.kuraimibank.com comment="Al Kuraimi Bank"
add dst-host=*.jeeb.ye comment="Jeeb Wallet"
add dst-host=*.floosak.ye comment="Floosak Wallet"
add dst-host=*.yemenmobile.com.ye comment="Yemen Mobile"
```

## 14. دليل المحاكي المحلي (server.ts) وبطاقات الفحص التجريبية

تم تزويد المشروع بمحاكي متقدم مبني بـ Node.js و Express يعمل على المنفذ `3000` ويحاكي استجابات راوتر ميكروتك الحقيقي بالكامل:

  ```bash
  npm run dev
  ```
* **رابط فتح البوابة محلياً:**
  `http://localhost:3000` أو `http://0.0.0.0:3000`

### بطاقات الفحص المبرمجة لاختبار سيناريوهات الأخطاء في المحاكي:
يمكنك إدخال أي من الأرقام التالية في حقل الكرت لتجربة استجابة رسائل الخطأ والنوافذ المنبثقة:

| رقم الكرت التجريبي | السيناريو المحاكى | رسالة الخطأ الناتجة في البوابة |
| :--- | :--- | :--- |
| `999` أو كرت يحتوي `used` | محاكاة كرت مستخدم في جهاز آخر | **الكرت مستخدم في جهاز آخر** |
| `888` أو كرت يحتوي `expired` | محاكاة كرت انتهى رصيده الزمني | **انتهى رصيد هذا الكرت** |
| `777` أو كرت يحتوي `profile` | محاكاة كرت انتهت صلاحية بروفايله | **انتهت صلاحية الرصيد** |
| `000` أو كرت يحتوي `notfound` | محاكاة كرت غير موجود في قاعدة البيانات | **المستخدم غير موجود** |
| `111` أو كرت يحتوي `mac` | محاكاة كرت مخصص لجهاز ذي ماك مختلف | **لا يمكنك استخدام هذا الرقم، لأنه تم تخصيصه لجهاز آخر** |
| **أي رقم كرت آخر** (مثال: `777723089`) | **تسجيل دخول ناجح** | تحويل فوري لـ `alogin.html` ثم `status.html` |
